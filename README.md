# Fair Clock

A food delivery platform where a late order becomes a transparent decision moment. Browse restaurants, build a cart, check out with the delivery promise shown up front, then track the order live. Delays are explained, priced automatically and resolved by the customer.

## Stack

Vite, React 18, TypeScript (strict), Tailwind CSS 3, Framer Motion, Lucide, custom SVG map.

## Run

```
npm install
npm run dev
```

Other scripts:

```
npm run typecheck
npm run build
npm run preview
```

## Real data and what is simulated

| Part | Source | Status |
|---|---|---|
| Your location | Browser geolocation, or address search (Nominatim) | Real |
| Restaurants near you | OpenStreetMap via the Overpass API | Real |
| Route and travel time | OSRM public routing, drawn as a custom SVG map | Real |
| Weather | Open-Meteo, polled every 2 minutes during a live order | Real |
| Menus and prices | Sample menus generated by cuisine, with veg and non-veg dishes, priced in INR | Sample |
| Restaurant acceptance, riders, payments | None | Simulated, no restaurant is contacted and no payment is taken |

Nothing is scraped from delivery apps. If a service is unreachable the app falls back to an estimated route, and the sample restaurants are always available.

## User flow

1. Restaurants: use your location or search an area, then filter by cuisine or search dishes.
2. Menu: veg and non-veg markers on every dish, an All, Veg and Non-veg filter, and how long each dish stays good after being cooked. All prices are in INR.
3. Checkout: the real route is fetched, the promised time and compensation rule are shown, and you choose a real-time order or demo mode.
4. Live tracking: the rider follows the real route. ETA range with confidence, audit ledger, impact strip, compensation clock, decision center and refund tracker.
5. Orders: history of delivered and cancelled orders, saved in the browser. Wallet credit from late deliveries can be spent at the next checkout.

## How the simulation works

`src/engine/simulation.ts` holds a pure reducer.

- Real-time mode: the clock runs at true speed. Arrival is preparation time plus the real route duration. No delay is scripted. A delay is added if the weather service reports rain that was not falling when you ordered.
- Demo mode: 1 real second equals 1 simulated minute, with a kitchen delay and a rider batching delay scripted.
- The promised time is 2 minutes after the first estimate. Compensation is 1% of the order total per minute after that, capped at 25%.
- Direct delivery saves about 5 minutes. Cancelling needs a 1.2 second press and hold and refunds the full total.
- The order, cart, history and wallet are saved in localStorage, and an order in progress catches up on elapsed time when the page reloads.

## Demo controls

Press `D` on the tracking screen or use the Demo button to trigger a kitchen, rider or rain delay, change speed (real time, x1, x3, x8) or restart the order.

## Project layout

```
src/data        sample restaurants
src/engine      simulation reducer, selectors and configuration
src/hooks       simulation loop, cart, persistence, press and hold, theme
src/components  views, tracking panels, decision center
src/lib         geo services, menus, formatting, pricing, order records, storage
```

A production version would replace the simulated parts with restaurant, dispatch and payment services behind the same state shape.
